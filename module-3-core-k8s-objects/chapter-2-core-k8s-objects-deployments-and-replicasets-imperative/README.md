# Chapter 2 — Core Kubernetes Objects: Deployments & ReplicaSets (Imperative)

A hands-on exercise guide exploring how to create, scale, update, inspect, and roll back Deployments and ReplicaSets imperatively using direct `kubectl` CLI commands.

---

## Step 1: Create an Initial Deployment

Create a Deployment directly from the command line without using a manifest file.

### Create Deployment with 2 Replicas
Deploys an NGINX workload named `myapp-deployment` with 2 replicas:
```bash
kubectl create deployment myapp-deployment --image=nginx:1.28.3 --replicas=2
```

### Verify Deployment and Pods
Check the status of the deployment and underlying pods:
```bash
kubectl get deployments
kubectl get pods -o wide
```

---

## Step 2: Scale the Deployment

Adjust the number of running replicas on the fly.

### Scale Up to 3 Replicas
Scales the deployment to 3 running pods:
```bash
kubectl scale deployment/myapp-deployment --replicas=3
```

### Verify Scale Status
Confirm that 3 pods are running and ready:
```bash
kubectl get deployment myapp-deployment
kubectl get rs
```

---

## Step 3: Upgrade Deployment Image (Rolling Update)

Perform a rolling update imperatively using `kubectl set image`.

### Update Container Image
Updates the container image to `nginx:1.30.4`:
```bash
kubectl set image deployment/myapp-deployment nginx=nginx:1.30.4
```

### Watch Rolling Update in Real-Time
Observe old pods terminating as new pods are created:
```bash
kubectl rollout status deployment/myapp-deployment
kubectl get rs -w
```

---

## Step 4: Inspect Rollout History and Revisions

Track historical revisions generated by updates.

### View Rollout History
Lists all revisions tracked for the deployment:
```bash
kubectl rollout history deployment/myapp-deployment
```

### Inspect a Specific Revision
Displays configuration details for revision 1:
```bash
kubectl rollout history deployment/myapp-deployment --revision=1
```

---

## Step 5: Roll Back Deployment Imperatively

Revert to a previous stable state using `kubectl rollout undo`.

### Undo Latest Rollout (Roll Back to Previous Version)
Rolls back to the previous revision:
```bash
kubectl rollout undo deployment/myapp-deployment
```

### Roll Back to a Specific Historical Revision
Explicitly rolls back to revision 1:
```bash
kubectl rollout undo deployment/myapp-deployment --to-revision=1
```

### Verify Rollback Completion
Confirm that the deployment returned to the target image version:
```bash
kubectl rollout status deployment/myapp-deployment
kubectl describe deployment myapp-deployment
```

---

## Step 6: Resource Cleanup

Remove the deployment and all associated ReplicaSets and Pods:
```bash
kubectl delete deployment myapp-deployment
```

---

## Quick Reference Summary

| Action | Imperative Command | Description |
| :--- | :--- | :--- |
| **Create deployment** | `kubectl create deployment <name> --image=<img> --replicas=<n>` | Create new deployment directly |
| **Scale replicas** | `kubectl scale deployment/<name> --replicas=<n>` | Scale pod count on the fly |
| **Update image** | `kubectl set image deployment/<name> <cname>=<img>` | Trigger rolling update |
| **Rollout status** | `kubectl rollout status deployment/<name>` | Stream update progress |
| **Rollout history** | `kubectl rollout history deployment/<name>` | View tracked revisions |
| **Undo rollout** | `kubectl rollout undo deployment/<name>` | Roll back to previous revision |
| **Roll back to revision** | `kubectl rollout undo deployment/<name> --to-revision=<n>` | Target specific historical revision |
| **Delete deployment** | `kubectl delete deployment <name>` | Tear down all deployment resources |
